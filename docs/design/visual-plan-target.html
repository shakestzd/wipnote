Decisions you will probably want to change

High tweak likelihood
Decided by you: ① one document per slice · ② explicit Send to Claude comment · ③ an approval carries over if the edit is minor · ④ anything except whitespace counts as a change · ⑤ the page shows a diff of what changed. Together, ③ and ④ mean an approval survives whitespace-only edits and nothing else, and ⑤ keeps a typo fix quick to re-approve. Toggle any choice to compare it with the alternative.

Each flagged choice shows the alternative. Toggle it and the schema on the right changes with it.

Choice ① · Review data shape Decided
Your pick · one document per slice

Each slice gets its own review document, so two reviewers on different slices never write to the same document.

  • Saves are last-writer-wins, so one document per slice stops reviewers overwriting each other.
  • Stale approvals can be flagged per slice.

Cost: reading a whole review means listing a collection instead of fetching one document.

Alternative · one document per plan

A single document holds every slice's decision. One read gets the whole review.

  • Simplest read-back.

Pick this if: there is only ever one reviewer. Two reviewers on different slices can overwrite each other.

Choice ② · How the session finds out Decided
Your pick · explicit "Send to Claude" comment

The reviewer presses a button that posts an artifact comment addressed to Claude. Tested: it woke the session within 20 seconds, while saving a decision woke nothing.

Cost: one extra click per review round, and only editors of the artifact can send to Claude.

Alternative · rely on the database write waking the session

No button. Every approval would notify the session directly.

Disproved: two decisions saved from the page woke nothing. Only a republish or a comment sent to Claude wakes the session.

Choice ③ · Approval after the slice is edited Decided
Your picks ③ and ④ · whitespace-only edits keep the approval

The approval is tied to a hash of the slice text with whitespace normalised. Re-wrapping a line or fixing indentation keeps it. Any other change, even a typo, clears it.

  • No judgement call about which fields matter.
  • A reviewer never approves text they have not seen.

Cost: a typo fix costs a re-approval, so the page shows what changed (decision ⑤). Open the Plan edited state in section B to see it.

Alternative · wording-only edits also keep the approval

Only changes to done-when, files, deps or a block clear the approval. Changes to the wording of what, why and decision notes keep it.

Pick this if: typo fixes should not cost a review round. It needs a list of material fields, and a reviewer can miss a wording change that shifted meaning.

F

Risks and mitigations

Only editors of the artifact can send to Claude, so a reviewer below editor access cannot notify the session.
MED
Fine for you reviewing your own plans. For a team, an editor relays the decision, or a different notification path is needed. Decide before slice 2.
Two reviewers saving the same document overwrite each other.
LOW
One document per slice. If several reviewers share a slice, key the documents by reviewer id.
A plan is edited after someone approved a slice.
MED
Key each approval to a hash of the whitespace-normalised slice text. Whitespace-only edits keep the approval. Any other change shows "changed since you approved" with a diff, and needs a fresh decision.
Slice titles and reviewer comments are untrusted text.
MED
Render only through textContent. No markup from data, ever.
Replacing the dashboard feedback path breaks existing plan reviews.
MED
Support both sources behind one reader until the artifact path has run on a real plan.
The clipboard may be blocked inside an artifact.
LOW
Fall back to a selected textarea. Not yet tested in an artifact.
