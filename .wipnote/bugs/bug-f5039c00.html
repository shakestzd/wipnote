Description

GitHub #194. Root cause is not the worktree: it is WIPNOTE_AGENT_ID, which wipnote exports into subagent sessions (worktree sessions are usually subagents). cmd/wipnote TestMain cleared only the harness-native session ids, so every runWiSetStatus start was attributed to a subagent and active_feature_id was never set. Reproduced: WIPNOTE_AGENT_ID=wipnote-feature-coder go test ./cmd/wipnote -run TestFeatureStart_Idempotent fails at workitem_test.go:881. Fix: new core/testenv.ClearAmbientSession (all WIPNOTE_* by prefix + named harness project/session/detection vars), called first in TestMain.
