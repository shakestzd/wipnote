Description

Codex P2 on PR #222 (comment 4309353516, cmd/wipnote/claude_launch_intent.go picksExistingSession). With launch_isolation: auto, a same-harness work-item row whose session ran in the project root has a valid resumeID and a non-empty workItem, so isolation stays on, creates .claude/worktrees/<item>, and runs claude --resume <id> there. Claude finds a transcript only from the directory it ran in, so the resume fails. Legacy claude-code rows, now normalized to claude, reach this path too. Fix: run an accepted direct resume in its recorded directory, or drop the resume ID and rehydrate when isolation moves the launch. Test with launch_isolation auto and a root-scoped session on a work item.
