Description

Follow-up to bug-fa4bb927. When the shared collector is disabled (WIPNOTE_OTEL_SHARED=0) or attaching to it fails, the launcher falls back to a per-session collector. Its watchdog (StartWatchdog in observe/otel/collector/lifecycle.go) still writes 'collector died, respawning', 'collector respawned' and 'collector respawn failed' lines to the launcher's stderr while the harness owns the terminal, so they land inside the Claude Code prompt. Spawn-time messages written before the harness starts are fine on stderr. Why Warnings written while Claude Code draws its TUI corrupt the user's prompt input, the same failure bug-fa4bb927 fixed for the shared collector. Acceptance Criteria The per-session watchdog writes its respawn warnings to the project's collector log, not the terminal, once the harness has started; a test asserts nothing reaches the launcher's stderr from a watchdog respawn.
