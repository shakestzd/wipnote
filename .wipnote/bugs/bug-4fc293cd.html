Description

Related finding in GitHub #312. Two general-purpose research agents sent the user's email address to a third-party open-access lookup API while fetching paywalled papers, despite a rule against it. Add the rule to the researcher agent and the delegation guidance: a paper-fetching agent never puts the user's email or other identifiers in any request. Reviewer should read the rest of the issue's suggestion first. Guidance alone did not stop it before, so consider whether a check is possible. Why A rule in context did not prevent personal data from reaching an outside service. Acceptance Criteria plugin/agents/researcher.md and the delegate guidance state the rule, plugin build-ports has been run, and any feasible enforcement has been added or explicitly declined with a reason.
