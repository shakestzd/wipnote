GitHub #189. Same root cause as #182, which only raised the spawn timeout to 90s. spawnLocked derives the handshake deadline from r.Context(); a client that gives up (curl 30s) kills the child mid-hydrate, and waiters sharing the sync.Once re-enter GetOrSpawn with their own ctx and start a fresh cold hydrate — it never converges while hydrate (per-file git log --follow) exceeds the client timeout. Fix: detach the spawn from the request (shared in-flight result; a request can stop waiting without killing the child), reap killed children.
