Description

GitHub #320. flush marks these intents ignored (not retried, not dead-lettered), so they stay pending forever and no command drops them (reporter saw 377 pending). Under WIPNOTE_ARTIFACT_COMMIT_POLICY=none, check --gate still blocks on the current item's own intent, and its advice is to stop ignoring .wipnote, which conflicts with a deliberate choice. Related to bug-e59a0d57, whose non-counting treatment of ignored paths matches this behaviour; check its status when fixing this. Also matters for keeping records out of a project's repo. Why Anyone who keeps wipnote records out of git on purpose cannot pass the gate, and the only workaround is hand-editing the outbox. Acceptance Criteria An intent whose path is ignored by git leaves the pending queue through dead-letter or a drop command, policy none no longer blocks the gate on any intent, and tests cover both.
