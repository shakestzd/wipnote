Description

findGlobSetDuplicate in core/arch/store.go rejects any new active card whose sorted path-glob set equals another card's, even when the kinds differ (decision vs hazard vs invariant about the same file). Users work around it by padding --paths with unrelated globs, which corrupts arch resolve --for results. The check should key on (kind, normalized glob set), or downgrade to a warning, so several distinct facts can be recorded against one file. GitHub issue #168.
