Description

An external project session exposed a compound cross-harness attribution failure. Invoking the Claude launcher inside an already-active Codex task attempted an interactive Claude process and failed after telemetry/dashboard startup errors, but left CLI identity bound to the launcher-created Claude session. Subsequent work-item start claims attached to that Claude session while the Codex PreToolUse hook checked the original Codex thread ID and blocked delegated and root edits as having no active work item. The who and session list/show commands then disagreed about the active session. Creating a work item in a read-only checkout also unexpectedly attempted launcher and collector startup instead of failing cleanly. Track under existing Workitem Attribution and Lineage; publish a GitHub issue with reproduction and expected behavior.
