arch validate: flag verified_at SHAs that are missing or unreachable from HEAD

Implementation Steps

  1. ⏳ Add a git-aware pass in runArchValidateAll/runArchValidateOne (cmd/wipnote/arch_cmds.go) using a gitCommitReachable helper that emits ERROR for missing and WARN for unreachable SHAs
  2. ⏳ Validate the SHA in runArchEdit when --verified-at is set unless --force
  3. ⏳ Add --commit-map <path> to arch repair that rewrites matching VerifiedAt values via store.Update
  4. ⏳ Add tests in cmd/wipnote/arch_cmds_test.go with an orphaned-commit fixture

Description

wipnote arch validate reports All arch cards are valid even when a card's verified_at points at a commit that no longer exists or is unreachable after a history rewrite, because Store.ValidateAll in core/arch only checks name, kind, word count and path shape. Validation should resolve each verified_at with git cat-file -e and git merge-base --is-ancestor and report failures, arch edit --verified-at should reject non-existent SHAs, and arch repair should accept --commit-map to re-pin cards in one pass. GitHub issue #173.
