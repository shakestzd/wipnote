Description

After plan reopen resets status to todo, createApprovedPlanFeatures in cmd/wipnote/plan_finalize_yaml.go creates a fresh feature for every approved slice and ignores PlanSlice.FeatureID, so previously promoted features become orphaned duplicates and their edges point at stale IDs. finalize-yaml should mirror promote-slice Rule 3: reuse an existing, still-present feature_id and only create features for slices without one, wiring blocked_by edges against the reused IDs. GitHub issue #116.
