Implementation Steps

  2. ⏳ Ledger: Store.Open on a closed row appends a run-start event (resume); on an open row it is a replay and writes nothing; Close ends the latest run; Enrich/Correct target the latest run; new Store.Ensure for late writers never resumes
  3. ⏳ procsweep: orphan status decided from the latest run (live while open; orphan if started at or before latest end + 2s; zero start stays orphan)
  4. ⏳ Committed b0b8ef750 (ledger runs, Store.Ensure, hook docs) and 6c3dba4e5 (procsweep latest-run rule) on obs/resume; gates green: root build/vet, darwin vet procsweep, go-test-streaming ./..., core go test ./...

Description

On claude --resume, sessionledger.Store.Open leaves the closed row alone and Close leaves an already-closed row untouched, so a resumed-then-exited session never records its second end. procsweep then treats processes started after the first end as live forever. Owner decision 2026-10-28: record each resume as a run on the session row (append-only events): a resume adds a run with its start, Close ends the latest run, lineage keeps the first start, and procsweep decides orphans from the latest run. Found by Codex review on PR 279.
