Codex review finding (deferred earlier). hookSubcmd calls OpenHookDB unconditionally for ~18 hooks (posttooluse, stop, subagent-start/stop, task-*): db.Open with WAL, busy_timeout 5000, _txlock=immediate and a migration check. The doc comment calls it a rare daemon-miss fallback. Contributes to #183-style sluggishness under many sessions (busy waits up to 5s per hook) but is not the serve freeze (serve_child uses in-memory projections). Needs the daemon-first refactor across the handler call sites; not folded into the #183 PR.
