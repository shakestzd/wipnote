Description

EnvSessionID in core/hooks/runner.go falls back to .wipnote/.active-session, which any harness SessionStart overwrites via WriteActiveSession, so wipnote bug start and wipnote who can bind claims to a nested launcher's Claude session while PreToolUse enforces against the payload session id. wipnote claude also launches Claude when stdin and stdout are not TTYs because the TTY check only gates the chooser. Make the resolver canonical by preferring the harness-native or payload id and treating .active-session as harness-tagged and stale-aware, and refuse interactive nested launches when non-interactive.
