DesignPending

Problem

Five read-only audits (spk-f72d2045, 2026-10-25) found about 10,000 lines of code left over from the removed dashboard, serve and SQLite eras, hot-path cost on every hook call, helpers copied up to ten times with drift, stale model ids and unused harness features. On the way they found correctness bugs that give wrong answers today: claims reconcile closes live sessions, every YOLO commit is blocked, claim release and heartbeat persist nothing. A re-check on v0.82.1 (87bc16d0d) confirmed 7 of 8 bugs are still present.

Goals

  1. Fix every confirmed correctness bug with a test that failed before the fix.
  2. Delete code with no production caller, measured by deadcode/unused tools, not by reading.
  3. Cut per-hook and slow CLI path cost with timings recorded before and after.
  4. Leave one copy of each shared helper and no file or function over the repo limits in touched code.

Constraints

  • Bugs are fixed before the code around them is deleted, so the evidence survives.
  • The canonical store (.wipnote HTML, ledgers, NDJSON, git) stays the source of truth; no slice adds a persistent SQLite file.
  • Daemons and hooks never block Claude (user rule).
  • Slice 6 coordinates with in-progress feat-fc3cc9e0 and does not redo its work.
  • Each slice runs as its own work item from wt-cleanup and passes the full suite before merge.
