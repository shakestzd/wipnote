Description

post-create.sh installs roborev, uv, oh-my-posh, oh-my-zsh and the agent CLIs but never installed herdr. The herdr CLI 0.9.5 (protocol 22) exists in the dev container only because it sits in the wipnote-local-bin named volume, installed by hand. delegate doctor's herdrCheck requires herdr on PATH and HERDR_ENV=1, so if that volume is ever recreated, delegate spawn breaks with no installer to restore it. Install via the herdr.dev installer, which ships the herdr CLI and honours HERDR_INSTALL_DIR. Do NOT use the releases.herdr.dev app installer: that ships the separate herdr-app GUI plus herdr-core/hc, which wipnote does not use and which are absent from this container. Also drop the stale ttyd row from the devcontainer README: ttyd left post-create when the web dashboard and wipnote serve were removed, so the table documents a tool the bootstrap no longer installs. Why Delegation silently breaks on a volume recreate because the devcontainer cannot reprovision its own herdr dependency. Acceptance Criteria A fresh post-create run installs the herdr CLI into the local bin dir and herdr is on PATH; the devcontainer README toolchain table lists herdr and no longer lists ttyd; shellcheck passes on post-create.sh.
