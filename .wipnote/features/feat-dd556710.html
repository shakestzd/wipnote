Description

wipnote delegate run prints nothing until the tool exits, and delegate watch covers only spawned workers, so a caller cannot follow a long one-shot run (codex exec, codex review, claude -p) under Monitor. Add --progress: one key=value line when the run starts, one per completed tool step, and a final done line with the exit status and the answer and run-page paths, in place of the report. Teach the delegate skill to arm Monitor on long runs. Why A long Codex review gave the caller no signal until it ended; Monitor can surface each step and a failure as it happens. Acceptance Criteria delegate run --progress emits started, step and done lines, tests cover it, and the delegate skill tells Claude Code callers to run long runs under Monitor with --progress.
