Description

Add the wipnote-orchestra Claude Code mod at mods/wipnote-orchestra/ beside wipnote-cards. It draws a band under the prompt: Claude Code's own hint line, a usage-limits row (5h/7d), wrapping powerline segments (repo, branch, model, context %, track [done/total], work item, live agents, time) and one row per subagent. It reads wipnote (kind show --format json, track show) and never writes to it. DECISIONS (a) Time zone: now a userConfig option timeZone, default America/New_York. zoneOf() falls back to the default for an empty or unknown IANA zone, so a typo cannot throw while drawing. The clock segment and the usage-limit reset times both use it. Tests: unit (zoneOf, localTime, limitSpans in UTC) and a mounted band with options {timeZone: UTC} vs default; mutation-checked (ignoring the option fails the UTC test). (b) Overlap with wipnote-cards. Shared field: the active work item. Cards shows its id, status and n/m steps in the status line, from the session claim (wipnote who). Orchestra shows its title and track [done/total] in the band, from wipnote start/complete commands seen in Bash. Both run wipnote <kind> show --format json for the same item. Only cards draws wipnote-ref cards; only orchestra shows the track, usage, agents and git. Risk: the two sources can name different items. Recommendation: merge into one mod (orchestra absorbs cards): the work-item segment adds status colour and n/m steps, the active item comes from wipnote who plus shell tracking, one poll per item, the fence cards move in, and the $.ui.status line is dropped. Fallback if kept apart: cards drops its status line (id/status/steps move into the orchestra segment) and keeps only fence cards. Not merged: waiting on the owner's decision. (c) Shipping: not built. Mods are separate Claude Code plugins (own plugin.json) and only Claude Code has the mod API, so they ship on the Claude target only. Proposed: build-ports copies mods/<name>/ (without tests/ and .claude-plugin/types/) into the bundled tree, e.g. share/wipnote/mods/<name>/, and wipnote claude adds one --plugin-dir per enabled mod, opt-in through config while the API is early access. A marketplace entry in .claude-plugin/marketplace.json is a cheap extra path for bare claude users. Tracked as the existing build-ports step in feat-a1df60c2.
