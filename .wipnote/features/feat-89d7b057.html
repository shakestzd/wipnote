Implementation Steps

  1. ⏳ In the in-progress branch of wiSetStatusWithAgent call canonicalLinkedCommits and print an advisory naming linked commits when non-empty
  2. ⏳ Run a bounded git grep for the item id excluding .wipnote and list hits
  3. ⏳ Keep it advisory and skip when not a git repo
  4. ⏳ Add workitem tests covering both signals and the silent path

Description

wipnote feature/bug/spike start claims an item without checking whether it was already fixed and never closed. The provenance helper canonicalLinkedCommits in cmd/wipnote/workitem_provenance_canonical.go already answers whether an item has linked commits but is only consulted at completion. Add a non-blocking advisory on start that names linked commits and reports git grep hits for the item id outside .wipnote/. GitHub issue #178.
