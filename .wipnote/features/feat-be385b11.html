# Spec: Question record and `wipnote question add|list|answer`

## Problem
Gives every open question a home that survives across turns and shows in lineage (goal 1). All later slices read or write this record.

## Decisions
**Trigger:** an orchestrator or worker runs `wipnote question add` on a work item.
**State:** a list of Question records in one node property, read and merged the way `research.FromNode` / `research.Merge` (core/research/record.go) handle the research record (cmd/wipnote/research_cmd.go saveResearchRecord, openItem). The field set extends planyaml.PlanQuestion (id, text, recommended, options, answer) with blocking, status, raised_by, raised_at, source_id, assumed, note and answered_at; the option `tradeoff` is a new field beside QuestionOption's key and label.
**Status:** open on add; assumed, confirmed and overturned are set by slice 2. `--force` re-answer exists so an overturned question can be corrected; slice 2 re-runs its overturn check on it.
**Payload:** `list --format json` rows carry item id, item title, question id, text, options, recommended, blocking, status, assumed, raised_by, age and answer, so the mod and the hook read one shape. Items that no longer resolve are skipped.
**Size:** list and its JSON rendering live in question_list.go so question_cmd.go stays under 500 lines once slice 2 adds assume.
**Rejected:** steps (a done-flag checklist, no options or answer); edges (relations, not payload); a separate questions/ directory of files (a second store to sync, and the answer would not sit on the item).
