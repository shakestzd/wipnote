# Spec: Ask with the question tool in batches; Stop hook nudge

## Problem
The owner asked for the question tool five times in one session; the rule and the nudge make it the default (goal 4).

## Decisions
**Trigger:** the Stop hook (hooks.Stop in core/hooks/missing_events.go, dispatched from cmd/wipnote/hook.go; manifest entry already targets claude, codex and antigravity).
**State:** reads open records via the slice 1 list. Loop guard is stop_hook_active, verified in both Claude Code and Codex docs; runner.go already parses last_assistant_message and gains StopHookActive.
**Workers:** delegated workers also fire Stop; the check skips sessions the delegate launcher marks as workers (WIPNOTE_DELEGATE_RUN is set; confirm it reaches the hook process during the slice), so only the orchestrator is nudged.
**Payload:** decision "block" with a reason naming the question ids and the tool to use. Codex uses the existing emitter (codexEventAcceptsDecision covers Stop in core/hooks/harness_response.go). Antigravity's Stop format is undocumented, so it gets the prompt rule alone.
**Rejected:** a context note only (prose questions still reach the owner first); no hook (owner chose block once).
